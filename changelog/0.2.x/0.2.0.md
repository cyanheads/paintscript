# 0.2.0 — 2026-11-25

## Changed

- **Journal replay** — `Painting.replay`, `replayJournal`, and `renderTimelapse` hold each replayed run to the painting's `limits.timeMs` and `limits.strokes`, where 0.1.0 applied neither. A run that passes a limit throws `budget_exceeded`, a new `PaintscriptError` code, naming the limit to raise (0.1.0 threw `invalid_journal` for the memory limit). The `paintscript replay` command and `run --timelapse` keep no time or stroke limit.
- **`Painting.view`** — rejects as `invalid_options` a `maxSide` below 16 or not a number, a `grid` outside 2–100,000, an unknown `mode` or `surface`, and an unknown option name. 0.1.0 raised a `maxSide` below 16 to 16 and ignored a `grid` of 0 or less.
- **`Painting.at`, `diff`, `image`** — `at` rejects a point that is not two finite numbers, `diff` a `cell` outside 4–4096, and `image` an unknown surface, each as `invalid_options`.
- **`renderTimelapse`** — `frames` × the GIF's width × height may come to at most 1 GiB of RGB; past that it throws `invalid_options` naming the frame count that fits.
- **Float error at a bound** — `stroke()` and `brush()` numbers, path pressure included, within 1e-9 of a bound are read as the bound, so a pressure or load computed a hair outside 0–1 is accepted.

## Security

- **Time limit and cancellation** — `limits.timeMs` and `cancelled()` now stop a run between vocabulary calls and inside a stroke, where the sandbox's interrupt does not reach. A stopped run does no more work and commits nothing.
- **Named brushes and palette colors** — a painting keeps at most 1,000 of each. Defining another is a script error, redefining an existing name still works, and an error that lists the defined names gives the first 40 and counts the rest.
- **`decodePng`** — reads at most 8192 × 8192 px and never inflates past the size the header declares; a larger image throws `invalid_image`.
